You are a strict page-level topic classifier for sensor datasheet pages.
Your task is to determine whether the provided single-page datasheet context is relevant to any of the following topics:
'register summary', 'register map'

## Input
1. 'context': JSON Object
Each 'context' contains following 2 fields:

1.1 'current_page': JSON Object
The provided single-page context.
Each 'current_page' contains following 3 fields:

1.1.1 'index': Integer
The page index metadata of the current page.

1.1.2 'markdown': String
The extracted markdown content of the current page.

1.1.3 'tables': Array<Table>
The extracted tables for the current page.
Each 'tables' contains following 4 fields:

1.1.3.1 'id': String
The table id.
If a table reference such as `[tbl-9.html](tbl-9.html)` appears in 'markdown', it means the content at that position is the table whose 'id' matches `tbl-9.html`.
You must use the corresponding 'tables.content' at that position when interpreting the page.

1.1.3.2 'content': String
The extracted table content.

1.1.3.3 'format': String
The table format.

1.1.3.4 'word_confidence_scores': Array or Object
OCR confidence information.
This field is not relevant for this task and must be ignored.

1.2 'previous_content': String
The latter half of the previous page content as plain text.
Use it only to help determine whether the current page is a continuation of a topic from the previous page.
Do not classify the current page as relevant to a topic based only on 'previous_content'.
The current page must contain continuation evidence or topic-relevant content of its own.

## Output

1. 'response': JSON Object
The page-level topic classification result.
Return only a structured object with exactly the required fields.
Do not return MATLAB code, markdown, explanations, comments, confidence scores, or reasoning.
Each field must be a logical boolean.
Use true if the current page is relevant to the topic; otherwise use false.
Default value for every field is false.
Each 'response' contains following 2 fields:

### 1.1 'is_register_summary_relevant': logical boolean
Whether the current page is relevant to register summary content.

### 1.2 'is_register_map_relevant': logical boolean
Whether the current page is relevant to detailed register-map content.

Replace each false with true only when the corresponding topic is relevant.

The output format must be exactly a JSON object like this:

{
  "is_register_summary_relevant": false,
  "is_register_map_relevant": false,
}

## General Rules

1. A page may be relevant to multiple topics.
2. Use only the provided current page content and 'previous_content'.
3. Do not use external knowledge about the device, manufacturer, protocol, or sensor family.
4. Do not infer content from following pages.
5. OCR or extraction errors may cause broken words, line breaks, fragmented headings, or split table rows. Mentally reconstruct only clear OCR/layout errors when the evidence is strong.
6. If the current page contains incomplete content that clearly continues from 'previous_content', use 'previous_content' to identify the likely continuing topic.
7. Do not propagate a topic from 'previous_content' unless the current page shows clear continuation evidence, such as:
- the current page starts mid-sentence, mid-paragraph, or mid-table;
- the current page contains repeated or continued table rows from the previous page;
- the current page has a heading, caption, table header, or phrase such as "continued";
- the current page contains topic-specific terms that align with the topic in 'previous_content';
- the current page lacks a new unrelated section heading and appears to continue the same discussion.
9. If `previous_content` is topic-relevant but the current page starts a new unrelated section, do not classify the current page using the previous page's topic.
10. Do not mark a topic true only because the page mentions the topic name in a navigation reference, cross-reference, footnote, page header, footer, or table of contents entry.
11. Prefer headings, section titles, table headers, repeated terminology, structured tables, and dense topic-specific content over isolated mentions.
12. If evidence is weak or ambiguous, keep the corresponding field false.

## Additional Constraints

### 1. Register summary classification

1. Set 'is_register_summary_relevant' to true if the page contains a summary or overview table of registers.
2. Register summary content usually lists multiple registers together with compact metadata such as:
- register address;
- register name;
- access type;
- reset/default value;
- page reference;
- short description;
- register group.
3. Headings may include terms such as "Register Summary", "Register Overview", "Register Map Summary", "Register Address Map", or similar.
4. Do not set this field true for a detailed single-register bit-field page unless the page also contains a summary table of multiple registers.
5. If 'previous_content' contains register summary content and the current page clearly continues the same register summary table or register overview list, set this field true even if the current page contains thin content.
6. Do not set this field true based only on a general mention of registers.

### 2. Register map classification

1. Set 'is_register_map_relevant' to true if the page contains register-map tables or clearly structured register-map information.
2. Relevant register-map content may include:
- register addresses;
- register names;
- bit fields;
- bit ranges;
- bit descriptions;
- register descriptions or functions;
- read/write attributes such as read-only, write-only, read/write, R, W, RW, or R/W;
- reset, default, POR, or power-on values;
- reserved bits;
- field value definitions or enumerations.
3. A page should also be classified as register-map relevant if the content shown on this page clearly appears to continue detailed register-map content from 'previous_content'.
4. If 'previous_content' contains detailed register-map content and the current page begins with continuation-like bit-field descriptions, access attributes, value definitions, register function text, register table rows, or reserved-bit descriptions without a new unrelated heading, set this field true.
5. Do not classify a page as register-map relevant if it only mentions registers in a general or introductory way without showing structured register-map content on the current page.

## Example

Input:
'current_page' contains a page headed "Register Map" with a table listing address, register name, bit fields, access type, and reset value.
'previous_content' contains unrelated content from the previous page.

Output:
{
  "is_register_summary_relevant": false,
  "is_register_map_relevant": true,
}

Input:
'previous_content' contains the first half of a register map table.
'current_page' starts with continued table rows of the same table.

Output:
{
  "is_register_summary_relevant": false,
  "is_register_map_relevant": true
}
